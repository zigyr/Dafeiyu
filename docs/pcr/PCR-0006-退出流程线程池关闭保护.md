## 1. 背景与问题

2026-10-31 23:52:44，用户在控制台点击「停止全部服务」后关闭程序，
`logs/console-error.log` 记录：

```text
Traceback (most recent call last):
  File "F:\dafeiyu\console\ui.py", line 1366, in on_stop_done
    self.service.refresh_status()
  File "F:\dafeiyu\console\service.py", line 55, in refresh_status
    self.pool.submit(job)
RuntimeError: cannot schedule new futures after shutdown
```

原因：

1. `stop_all` 完成 → `stop_done` 信号 → `on_stop_done`；
2. 用户选择了「退出并停止服务」时，`_quitting=True`，`on_stop_done` 调 `_do_quit()`；
3. `_do_quit()` 调 `service.shutdown()`，线程池关闭；
4. `on_stop_done` 随后仍执行 `self.service.refresh_status()`，向已关闭的线程池提交任务；
5. 同时 `Service.stop_all` 的 job 在 `stop_done` 之后还会发 `status_ready`，可能继续触发刷新。

这不影响 NapCat 启动修复，但退出流程会留下异常日志，且违反“关闭后不再调度”。

## 2. 需求提炼

- **问题**：线程池关闭后仍有 `refresh_status` / `status_ready` 调度。
- **目标（可验证）**：
  1. `Service` 增加 `_closed` 状态，`shutdown()` 幂等；
  2. 所有 `pool.submit` 经统一 `_submit()`，关闭后直接返回 False；
  3. 关闭后不再发 `status_ready` / `qr_ready` / `log_ready` 等后续信号；
  4. `on_stop_done` 在“退出并停止”分支调用 `_do_quit()` 后立即 return；
  5. `stop_all` 在 `stop_done` 后仅在线程池未关闭时刷新状态。
- **非目标**：
  - 不改变停止/退出的用户可见选项；
  - 不改变后台服务行为。

## 4. 方案与取舍

| 方案 | 说明 | 取舍 |
| --- | --- | --- |
| A（采纳） | 统一 `_submit` + `_closed`，关闭后静默丢弃任务 | 简单、彻底，所有入口一致 |
| B | 只在 `on_stop_done` 加 `if not quitting` | 其他信号/定时器仍可能触发，修不干净 |
| C | `shutdown(wait=True)` 阻塞退出 | 可能卡住 UI，且不解决后续提交 |

## 5. 实施计划

1. `Service.__init__` 增加 `_closed=False`。
2. 新增 `_submit(fn)`：关闭或 `RuntimeError` 时返回 False。
3. 替换全部 `pool.submit`；各入口检查 `_closed`。
4. `stop_all` 发 `stop_done` 后，仅在未关闭时发 `status_ready`。
5. `shutdown` 先置 `_closed=True` 再关闭线程池。
6. `on_stop_done` 退出分支 `_do_quit()` 后 return。
7. 用“关闭后调用 refresh/stop/read”做守卫测试，更新文档并提交。

## 6. 验收标准
