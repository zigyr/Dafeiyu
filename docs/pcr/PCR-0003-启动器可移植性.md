## 1. 背景与问题

旧启动器 `大肥鱼控制台.vbs` 把两个绝对路径写死：

```vbs
sh.Run """F:\Compilers\python3\pythonw.exe"" ""F:\dafeiyu\console\app.py""", 0, False
```

影响：

1. **换机 / 移动目录即失效**：项目换到 `D:\`、U 盘、另一台电脑时，必须手改 VBS；
2. **Python 路径变化即失效**：升级 / 重装 Python、换 `F:\Compilers\python3` 后启动失败；
3. **失败无提示**：`sh.Run` 失败时用户只看到“没反应”，不知道是 Python 还是 app.py 找不到；
4. 交接文档「待办与后续」已登记「启动器可移植性」，但尚未实施。

## 2. 需求提炼

- **原始诉求**：继续推进交接文档待办；启动器不再依赖写死的 Python 与项目路径。
- **目标（可验证）**：
  1. VBS 通过 `WScript.ScriptFullName` 推导项目根目录，`app.py` 用相对路径拼出；
  2. 依次从 `DAFEIYU_PYTHONW` 环境变量、项目内 `python\`、常见 Python 安装目录、`PATH` 中查找 `pythonw.exe`；
  3. 找不到 `app.py` 或 `pythonw.exe` 时弹出清晰的中文提示，而不是静默失败；
  4. 仍然使用 `pythonw` + 隐藏窗口启动，不产生控制台黑框；
  5. 在任意工作目录下双击 / 用 `cscript` 调用都能启动。
- **非目标**：
  - 不改变 `app.py`、`settings.py` 或界面行为；
  - 不引入安装器 / 打包 exe；
  - 不改变开机自启注册表命令（`settings.py` 已使用 `sys.executable` 与 `__file__`）。

## 4. 方案与取舍

| 方案 | 说明 | 取舍 |

| A（采纳） | VBS 相对路径 + 多级 Python 发现 + 中文错误框 | 无依赖、改动小、兼容旧机器 |

## 5. 实施计划

1. 重写 VBS：推导 `base`，校验 `console\app.py`。
2. Python 发现顺序：`DAFEIYU_PYTHONW` → 项目内 `python\` → 常见目录 → `PATH`。
3. 失败时 `MsgBox` 给出缺失项与解决建议；`WScript.Quit 1`。
4. 设置 `CurrentDirectory = base`，用隐藏窗口 `Run`。
5. 从非项目工作目录调用验证；更新文档、PCR 索引、交接文档并提交。
